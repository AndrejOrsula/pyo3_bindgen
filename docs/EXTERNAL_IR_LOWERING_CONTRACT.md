# External-IR (`--ir`) lowering contract

**Audience:** anyone whose tool emits a `SchemaIr` JSON for pyo3_bindgen's `--ir` path.
This is the guarantee you target, so you can *read* the lowering instead of
reverse-engineering the emitter.

**Scope & stability.** The mappings below are the intended, tested contract of the `--ir` path. They are
guarded by the fixture in `crates/pyo3_bindgen_engine/tests/ir_hierarchy_compile.rs`
(`external_ir_contract_shapes_lower_as_documented` + the flag-enum and no-forwarders oracles): every row
that changes must change that fixture too. Treat a mapping change as an **emission-changing** release
(see "Versioning").

## Wire document, limits, and identity

`--ir` accepts two v1 wire shapes. Existing producers may keep emitting the unversioned legacy root:

```json
{"modules": []}
```

Legacy v1 preserves existing lowering and generated bytes. Unknown fields remain accepted for
compatibility, but each ignored field produces an `ir_legacy_unknown_field` warning with its complete
serde path. `--deny-warnings` and `--warning-budget` apply to these warnings.

New producers should emit the explicit current envelope:

```json
{
  "schema_version": 1,
  "schema": {"modules": []},
  "extensions": {}
}
```

Current-version documents reject unknown fields everywhere except inside the optional `extensions`
object. The pair of root keys `schema_version` and `schema` claims the envelope; a lone unknown
`schema_version` in a legacy root remains a compatibility warning. The version must be the unsigned
JSON integer `1` (mathematically equivalent spellings such as `1.0` and `1e0` are accepted);
unsupported versions fail at the wire boundary before schema validation or lowering. The checked-in current schema is
`schemas/schema_ir.v1.json`. The envelope is private transport policy: the public in-memory
`SchemaIr` type and its legacy serde identity do not contain version fields.

A hand-authored conformance corpus exercises the same raw documents through the checked schema,
the CLI envelope decoder/recursive allowlist, and the public `SchemaIr` DTO. The corpus records
intentional differences rather than claiming false parity: the public DTO alone ignores unknown
serde fields, the current CLI envelope and schema reject them, and legacy CLI input accepts them
with path-qualified warnings. Schema-semantic errors remain a later generation boundary.

The CLI accepts at most 64 MiB by default; `--max-ir-bytes <BYTES>` selects another raw-byte limit.
The reader probes at most one sentinel byte beyond that accepted limit and rejects an oversized
snapshot before UTF-8/JSON decoding. One owned accepted-byte snapshot is parsed and remains
authoritative even if the path is rewritten afterward. Reports retain both identities:

- `external_ir_input` diagnostic path and external module `source_hash`: SHA-256 of the exact raw
  snapshot, formatted `sha256:<64 lowercase hex>`;
- module `input_hash` and generated provenance constants: the existing deterministic FNV-1a
  fingerprint of normalized per-module IR.

SHA-256 proves wire-content identity; FNV preserves existing deterministic generation and drift
compatibility. Neither path identity nor a later reread substitutes for captured bytes.

Programmatic `module_from_ir`/`modules_from_ir` calls accumulate raw schemas without validating or
lowering the growing graph. Source-mode and bounded transport failures remain registration-time
errors. Schema-semantic validation and lowering happen exactly once when `generate`,
`generate_with_report`, or `build` consumes the complete graph, so those errors are deliberately
terminal. Batch and incremental registration of the same ordered modules produce identical
canonical bytes. See [`RESOURCE_BUDGETS.md`](RESOURCE_BUDGETS.md) for the pre-validation graph
limits and migration details.

The built-in external-IR path is Python-execution-free: registration, validation, lowering,
emission, and report generation do not initialize, attach to, import from, or execute Python and do
not populate Python runtime metadata. PyO3/libpython may still be a build or link requirement. A
custom `BindingSource` adapter's acquisition work is outside this guarantee until it returns its
materialized external schema.

## Type lowering

`T_owned` is the getter-return / owned type; `T_param` is the parameter / setter-input type. Both are
produced from one Python annotation string.

| IR annotation | `T_owned` | `T_param` |
|---|---|---|
| `int` | `i64` | `i64` |
| `float` | `f64` | `f64` |
| `str` | `String` | `&str` |
| `bool` | `bool` | `bool` |
| `bytes` | `Vec<u8>` | `&[u8]` |
| `bytearray` | `Bound<'py, PyByteArray>` | `&Bound<'py, PyByteArray>` |
| `Optional[T]` | `Option<T_owned>` | `Option<T_owned>` |
| `list[T]` | `Vec<T_owned>` | `&[T_owned]` |
| `set[T]` where `T` is hashable, including `bytes` and a **mirror enum** | `HashSet<T>` | `&HashSet<T>` |
| `set[T]` where `T` is a class / non-hashable | `Bound<'py, PySet>` | `&Bound<'py, PySet>` |
| `dict[K, V]`, `K` hashable (including `bytes`) or a **mirror enum**, & `V` typed | `HashMap<K, V>` | `&HashMap<K, V>` |
| `dict[K, V]` otherwise (non-hashable/class key, or `V` untyped) | `Bound<'py, PyDict>` | `impl IntoPyDict<'py>` |
| `tuple[...]` (≥2 non-`...`) | `(T0, T1, …)` | ditto |
| `Collection[T]` (CR5, IR-only) | lazy opaque `PyCollection<T>` view | `&PyCollection<T>` |
| `Array[T; d1, d2, …]` (CR7, IR-only) | `[T; d1]` / nested `[[T; d2]; d1]` | ditto |
| a **mirror-enum** reference | the mirror `enum` type | the mirror `enum` type |
| a **class** reference (in the IR) | that class newtype | that class newtype |
| a reference to a type **omitted from the IR** | `Bound<'py, PyAny>` | `impl IntoPyObject<'py>` |
| `Union[...]`, `Any`, unresolved | `Bound<'py, PyAny>` | `impl IntoPyObject<'py>` |

**The omitted-type rule is the one you rely on most:** a property/param/return whose annotation names a
type your IR does not define lowers to `Bound<'py, PyAny>` (owned) — it is **never** a dangling reference
to the missing name. So you may prune types from the IR freely; references to pruned types degrade, they
do not break the build. (Note: the owned type is `Bound<'py, PyAny>`, not `Py<PyAny>`.)

**Container elements never borrow.** In parameter position only the *outermost* type borrows; a
container's element type stays the owned `T_owned`. So an `Optional[str]` parameter is `Option<String>`
(not `Option<&str>`), a `list[str]` parameter is `&[String]` (not `&[&str]`), and a `dict[str, int]`
parameter is `&HashMap<String, i64>`. The `T_param` column is the top-level call-facing form (a
borrow or conversion trait where shown); nested elements read from the `T_owned` column.
Consequently, byte keys and set items are owned `Vec<u8>` values, not borrowed slices. `bytearray`
remains unhashable for typed container lowering.

`Collection[T]` lowers to a lazy, opaque typed view. `PyCollection<T>` extraction only retains the
Python object handle; it performs no collection-protocol or element validation. `len`, `get`,
`get_by_key`, and `iter` invoke their corresponding Python operations when called. `get(index)`
converts only Python `IndexError` to `None`; `KeyError`, `TypeError`, and every other Python error
propagate. `get_by_key(key)` converts only Python `KeyError` to `None`; `IndexError`, `TypeError`,
and every other Python error propagate.

## Structural lowering

| IR shape | Lowering |
|---|---|
| read-only property (`readonly: true`) | getter only, **no** `set_*` |
| mutable property | getter **and** `set_<name>` setter |
| instance method | `fn <name>(&self, py, …) -> PyResult<Ret>` (dedup: a `*Methods` trait default method) |
| constructor (`__init__`) | inherent `pub fn new(…)` on the newtype |
| static / class method | inherent `pub fn` on the newtype |
| class with in-IR bases | `#[repr(transparent)]` newtype + `<Base>Methods` supertraits + zero-cost upcasts |
| wrapper boilerplate | inherent `from_py_any` and `into_py_any`; `bind`/`as_any` are `PyObjectBase` default methods and `clone_ref` is a `PyTypeMarker` default method (both traits `pub` at the generated root, implemented by every generated Python class newtype, not auxiliary wrappers such as `PyCollection`) — bring them into scope to call them. `into_py_any` stays inherent on purpose: PyO3's `IntoPyObjectExt` blanket impl supplies the same name, so a trait-level copy would be ambiguous (E0034) for consumers importing it |
| **base class not in the IR** | **hard error** — the one non-degradable rule (fix your IR: include the base, or drop the `base_classes` entry) |

> **Emission-scope caveat.** "Not in the IR" means absent from the *schema*. A base that *is* in the IR
> but lies outside the **emission scope** — e.g. it lives in a sibling submodule and `traverse_submodules`
> is off — is not a hard error: its `<Base>Methods` supertrait and zero-cost upcast are dropped with a
> `base_class_out_of_scope` **warning**, and the subclass still generates without that base's inherited
> surface. Keep every class you name as a base inside the emitted set (the default
> `traverse_submodules = true` does this) to retain the supertrait wiring.

## Enum semantics

`Config::generate_enums = false` is an owning gate: every `EnumIr` is omitted, including any
`enum_ir_class_fallback` wrapper that would otherwise replace a non-representable mirror. Authored
`ClassIr` entries remain governed independently by `generate_classes`. The same no-enum/no-fallback
rule applies to live introspection.

| IR shape | Default (strict) | `--lenient-ir` |
|---|---|---|
| ordinary enum | mirror `enum` | mirror `enum` |
| `IntEnum` with full, unique values fitting one `i64`/`u64` repr | explicit discriminants + derived `Ord` | same |
| `is_flag` or `is_open` enum, no `plain_mirror` | **hard error** (honest refusal) | plain mirror `enum`; its `set[...]` properties lower to `HashSet<MirrorEnum>` |
| `is_flag` or `is_open` enum with `plain_mirror: true` | plain mirror `enum` (identical to the lenient lowering); its `set[...]` properties lower to `HashSet<MirrorEnum>` | same |
| enum with unrepresentable/colliding member idents, a dangling alias target, or no members | **hard error** (honest refusal) | still a **hard error** — this is `--enum-class-fallback`'s job, not `--lenient-ir`'s (see below) |

A flag enum's mirror represents **individual members**; a bitwise **combination** outside the member set
is not representable through `HashSet<MirrorEnum>` (that is pinned's contract too). If you need the lossy
combined value, see "Raw-fallback" below.

### Per-enum string-backing (`EnumIr.string_backed`)

Each enum object in the IR carries its own optional `string_backed` field (`bool`, JSON default
`false`, `#[serde(default)]`) alongside `is_flag`/`is_open`. When `true`, that enum's mirror
round-trips through its member **name string** (`as_py_name`/`from_py_name`) instead of importing
a backing Python `enum` class and reading `.name` off an instance — the same runtime conversion the
global `--enum-string-backed` flag (`Config::enum_ir_string_backed`) selects, but scoped to a single
enum rather than the whole document. This is the first-class mechanism for producers such as
Blender's RNA, where individual enum-shaped properties are plain strings with no importable class,
while other enums in the same document are real Python enum classes.

Effective string-backing for a given enum is the **logical OR** of the global flag and this field:
`cfg.enum_ir_string_backed || enum_ir.string_backed`. Either source alone is sufficient; setting both
is redundant, not conflicting. Absence of the field (or an explicit `false`) with the global flag also
off preserves the historical class-import mirror byte-for-byte — this field's addition is byte-neutral
for every pre-existing IR document.

### Per-enum flag/open opt-in (`EnumIr.plain_mirror`)

Each enum object also carries its own optional `plain_mirror` field (`bool`, JSON default `false`,
`#[serde(default)]`), alongside `is_flag`/`is_open`/`string_backed`. Setting it to `true` on an enum
that also sets `is_flag` and/or `is_open` is an explicit, per-enum producer sign-off: "I know this
enum's flag/open semantics are dropped by this generator, emit the plain mirror anyway." With it,
**strict** external IR (the default, non-lenient config) accepts that one enum and lowers it exactly
like `--lenient-ir` lowers the same flag/open enum today — same plain `enum`, same `HashSet<MirrorEnum>`
for its `set[...]` properties. Without it, strict validation keeps rejecting `is_flag`/`is_open`
unchanged; `--lenient-ir` is unaffected either way (a document already accepted under `--lenient-ir`
keeps working with or without `plain_mirror` set). Absence of the field (or an explicit `false`)
preserves the historical strict-rejection behavior byte-for-byte — this field's addition is
byte-neutral for every pre-existing IR document.

Use `plain_mirror` when only selected flag/open enums should opt into lossy mirrors;
strict validation continues to reject other flag/open enums in the same document.

For producers migrating from document-wide policy, the legacy invocation
`pyo3_bindgen --ir schema.json --lenient-ir --enum-string-backed` is equivalent to
`pyo3_bindgen --ir schema.json` after the producer stamps `plain_mirror: true` on each accepted
flag/open enum and `string_backed: true` on each enum represented by member-name strings. The flags
remain supported for incremental migration or genuinely document-wide policy.

### Non-representable enum fallback (`--enum-class-fallback`)

Off by default, an enum that cannot be lowered to a Rust mirror `enum` — because a member (or alias) ident
is unrepresentable or collides (e.g. `red` and `RED` both fold to `Red`), an alias targets a missing
canonical member, or the enum has no members — aborts the whole generation. With
`--enum-class-fallback` (`Config::enum_ir_class_fallback`) such an enum instead degrades to an **owning
Python object wrapper** (the same class newtype it would have been if authored as a `ClassIr`), reported
under the `enum_ir_mirror_fallback` diagnostic code. Consequences:

- every reference to the enum lowers to the owning newtype (as any class reference does), and
- `set[E]` degrades from `HashSet<E>` to `Bound<'py, PySet>` — a class newtype derives only `Debug`, so a
  typed `HashSet<E>` would not compile.

This is a **public-API change** (signatures that named the enum now name an opaque newtype), which is why
it is opt-in and carries a warning per fallen-back enum. It is deliberately **not** folded into
`--lenient-ir`. It does not touch the two other IR enum aborts: `is_flag`/`is_open` (that is
`--lenient-ir` or the per-enum `plain_mirror` field above) and an unrepresentable *enum name* (a class
symbol fails identically, so a fallback cannot help).

## Parameter grammar

| IR shape | Lowering |
|---|---|
| required positional after a defaulted one | lowered unchanged, unconditionally (strict **and** `--lenient-ir`) — a Python default never reaches the Rust signature (`has_default` is emission-metadata only), so order is irrelevant |
| multiple `*args` / `**kwargs`; a variadic with a default; duplicate/colliding names | **hard error**, unconditionally (strict **and** `--lenient-ir` — leniency never covered the structural parameter grammar, only the order rule above, which is now unconditional) |

## Determinism

`generate(sameIR)` is **byte-stable across runs** — no `HashMap`/`HashSet` iteration order leaks into the
output (name sets are sorted before emission). Guarded by
`external_ir_contract_shapes_lower_as_documented` (regenerate-twice equality) and
`ir_input_hash_is_stable_across_regenerations`. This is what makes a downstream
`committed == verbatim generator output` drift check stable.

## Flags (the consumer interface)

| Flag | Config field | Effect | Default |
|---|---|---|---|
| `--lenient-ir` | `lenient_external_ir` | accept flag/open enums without a per-enum `plain_mirror` opt-in; required-after-default ordering is accepted in either mode | off (strict) |
| `--no-inherent-forwarders` | `generate_inherent_forwarders` (inverted) | drop the inherent per-method forwarders; members reached via `*Methods` traits | forwarders on |
| `--enum-class-fallback` | `enum_ir_class_fallback` | degrade a non-representable enum to an owning class newtype instead of aborting (see "Non-representable enum fallback") | off (abort) |
| `--enum-string-backed` | `enum_ir_string_backed` | whole-document override: round-trip **every** mirror enum's values as the member **name string** rather than importing a backing Python `enum` class — for documents where no enum has an importable class. Prefer the per-enum `EnumIr.string_backed` field (see "Per-enum string-backing" above) when only some enums need it; the two combine with a logical OR | off (import backing class) |

These flags, plus the **`SchemaIr` JSON field names and semantics**, are a public interface: they are
not renamed, removed, or repurposed without a major version bump and a release-notes entry.

## Raw-fallback escape hatch (IR path)

`Config::enum_raw_fallback_paths` routes a specific enum to a raw `Py<PyAny>` wrapper — but it is honored
only on the **live-introspection** path today, **not** on `--ir`. On the `--ir` path you already hold the
escape hatch, because *you author the IR*: to keep a lossy type as an opaque handle, do **not** emit it as
an enum — either omit it (a reference to it then degrades to `Bound<'py, PyAny>` per the omitted-type
rule) or model it as a class. No engine patch is required. (First-class `--ir` support for
`enum_raw_fallback_paths` is a possible future additive feature; the IR-authoring workaround exists now.)

## Versioning

Wire version and report version are separate. External IR currently uses wire version 1. The
generation report remains schema version 1 because this contract reuses existing diagnostic and
`source_hash` fields rather than adding a serialized shape.

- **Byte-identical refactor** of `--ir` output → a consumer's drift check alone re-validates (cheap).
- **Emission-changing** release (any row above changes, or output bytes move) → a consumer must re-run
  its behavioral suite, since method/enum *bodies* — not just types — may have changed.

Each release states which it is. The flags and the `SchemaIr` schema follow semver: a breaking change to
either is a major bump, recorded in the corresponding release notes.
