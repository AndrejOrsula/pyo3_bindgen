# Agent guide

Read [README.md](README.md), the [release plan](docs/release_checklist.md), and the
relevant contracts in [docs/README.md](docs/README.md). Code and tests govern behavior;
the release plan owns all unfinished work. Keep completed plans and reports in Git history.

## Boundaries

- Dependency direction: CLI → facade → engine; macro → engine. See
  [workspace packages](crates/README.md) and [architecture decisions](docs/ARCHITECTURE_DECISIONS.md).
- One source mode per `Codegen`. Built-in external IR never executes Python; live
  generation and macros execute trusted Python. Preserve the single-interpreter contract.
- Preserve public identities, wire fields, deterministic output/reports/hashes, and exact
  adaptive selection. Change external-IR contracts and compile oracles together.
- Preserve distinct IR/output/report identities, locks, path revalidation, symlink rejection,
  atomic replacement, permissions/ACLs, and caller-specific durability outcomes.
- Libraries emit `tracing` events; only applications install subscribers.

## Work

- Inspect `git status --short --branch` before and after; preserve unrelated changes and
  the active branch. Commit, push, publish, and sibling writes require user authorization.
- Start architecture work with `cargo metadata --no-deps --format-version 1`.
  Cargo names the examples package `pyo3_bindgen_examples`.
- Use system temporary directories for scratch work and generated consumers.
- Verify external-IR and live-generation impact through approved downstream
  checkouts, read-only, or through temporary consumers. Keep downstream policy
  outside the engine; downstream writes require separate authorization.
- Review changed generated bytes as an interface diff; compile a representative consumer.
  Update the existing release plan and affected contracts instead of adding another plan.

## Checks

Run focused tests first, then applicable workspace gates:

```sh
cargo fmt --all --check
cargo check --workspace --all-targets --all-features --locked
cargo test --workspace --lib --bins --tests --examples --all-features --locked
cargo test --workspace --doc --all-features --locked
cargo clippy --workspace --all-targets --all-features --locked --no-deps -- --deny=warnings
cargo doc --workspace --all-features --locked --no-deps --document-private-items
```

Documentation: `scripts/check-docs.sh`. Release/configuration: CLI `release_config`
and `tooling_contract` tests. Generated types: both isolated `feature_bindings` feature
cases. Release commands and platform/interpreter gates live in the release plan.
Benchmarks require explicit authorization. Optional/ignored tests and cross-compilation
are not native runtime proof; require `PYO3_BINDGEN_REQUIRE_GYMNASIUM=1` for dogfood evidence.
